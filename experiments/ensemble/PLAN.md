## 0. 먼저 — 요청하신 7개 작업 중 2개는 이미 v9 안에 있습니다

계획을 쓰기 전에 `submit_v9.zip` 내부를 열어 확인했습니다(읽기 전용).

```
A7  (LightGBM, weight 0.25, feats 93)
     group G1 / X63 / X31lo / X63ff3   각 boosters 3
A9  (LightGBM, weight 0.30, feats 101)
     group G1 / X63 / X31lo / X63ff3   각 boosters 3
BCAT (CatBoost, weight 0.45)  cat_0.cbm + cat_1.cbm

LightGBM booster 24개 + CatBoost 2개 = 총 26개 모델
shrink 1.1 · shift -0.04 · 최종 가중 {A7 0.25, A9 0.30, BCAT 0.45}
```

| 요청 작업 | 상태 |
|---|---|
| 3. LightGBM seed ensemble | **이미 구현됨** — 2 family × 4 group × **3 seed** |
| 4. CatBoost seed ensemble | **이미 구현됨** — cat_0 / cat_1 |
| 7. OOF 기반 최적 weight 탐색 | 아래 §2에서 **여지 없음**으로 실측됨 |
| 1. pipeline 분석 | §1 |
| 2. OOF 생성 구조 설계 | §3 |
| 5. XGBoost 추가 | §4 — **유일하게 새로운 축** |
| 6. 모델별 prediction 저장 | §3 |

`groups`의 G1 / X63 / X31lo / X63ff3는 seed가 아니라 **feature·파라미터 변형**입니다.
즉 v9는 이미 (변형 4 × seed 3) 구조의 2단 앙상블입니다.

## 1. 현재 v9 prediction pipeline

```
raw row ──► featurize(carry, split, role, lowrank)   테이블은 시즌<S 에서만 적합·동결
                │
                ├─► numeric feats 101 ──► level logreg ──► init (log-odds)
                │
                ├─ A7   feats 93  : 4 group × 3 seed, seed 는 raw-score 평균,
                │                   group 은 확률공간 평균, init 을 init_score 로
                ├─ A9   feats 101 : 동일 구조
                └─ BCAT b_feats 68 (cat 4) : cat_0/cat_1 평균, shift -0.04

        p = 0.25·A7 + 0.30·A9 + 0.45·BCAT      (확률공간 고정가중)
```

`script.py`의 결합 규칙: *"Seeds average in raw-score space, groups in probability
space -- the order the backtest measured."*

### 1.1 구성요소 간 상관 — 다양성이 이미 낮습니다

로짓 공간 상관:

| | A7–A9 | A7–BCAT | A9–BCAT |
|---|---|---|---|
| 2023 | 0.9176 | 0.4499 | 0.2462 |
| **2024** | **0.9648** | **0.8102** | **0.8273** |

2024에서 세 구성요소가 전부 0.81 이상으로 붙어 있습니다. **앙상블이 짜낼 수 있는
다양성이 이미 거의 소진된 상태**입니다.

2023에서 BCAT의 상관이 0.25~0.45로 낮은 것은 다양성이 아니라 **BCAT가 그 시즌에
크게 어긋나 있었다**는 뜻입니다(§2 참조).

## 2. 가중치 재탐색 — 실측 결과 여지가 없습니다

기존 `work/research/oof_{2023,2024}.parquet`에 `p_A7` / `p_A9` / `p_Bcat`이
이미 있어 재학습 없이 즉시 측정했습니다.

### 2.1 고정 가중 격자 탐색 (0.05 간격, 합=1)

| 시즌 | 현재 (0.25,0.30,0.45) | in-sample 최적 | 이득 |
|---|---|---|---|
| 2024 | BSS **917.2** | (0.25, 0.25, 0.50) BSS 917.6 | **+0.4** |
| 2023 | BSS 403.1 | (0.45, 0.55, **0.00**) BSS 876.8 | +473.7 |

**2024에서는 현재 가중치가 이미 최적입니다.** 격자 전체를 뒤져도 +0.4입니다.

2023의 +473.7은 "BCAT를 완전히 빼라"는 해입니다. 그리고:

```
TEMPORAL: 2023 최적 (0.45, 0.55, 0.00) → 2024 적용
  BSS 917.2 → 838.1    dBSS -79.0    paired -79.9 ± 11.0
```

### 2.2 결합 방식 자체를 바꿔도 마찬가지

| 방식 | 2024 dBSS |
|---|---|
| 같은 가중치, 확률공간 → **로짓공간** | +0.1 |
| 로짓 stacking, **2024 in-sample (상한)** | **+19.4** ± 5.4 |
| 로짓 stacking, **2023 적합 → 2024** | **−154.3** ± 14.1 |

stacking 계수를 보면 원인이 분명합니다.

```
2024 적합 계수  [절편 -0.024,  A7 0.422,  A9 0.166,  BCAT 0.477]
2023 적합 계수  [절편 +0.020,  A7 0.496,  A9 0.523,  BCAT -0.068]
```

**BCAT 계수의 부호가 뒤집힙니다** (+0.477 vs −0.068). 2023에서 BCAT는 빼야 할
모델이고 2024에서는 가장 중요한 모델입니다. 어떤 결합 가중치도 이 반전을 넘지
못합니다.

### 2.3 결론

- **결합 최적화의 in-sample 상한이 +19.4**이고, 그마저 시즌을 넘기면 **−154.3**입니다.
- 프로젝트 채택 기준 `dRes ≥ 20`(STRONG) / `< 10`(WEAK)에 비추어 **상한 자체가 STRONG에
  못 미칩니다.**
- 요청 7번(OOF 기반 최적 weight 탐색)은 **수행할 가치가 없습니다.** 이미 수행했고
  답이 나왔습니다.

## 3. OOF prediction 생성 구조 (요청 2·6번)

새 모델을 평가하려면 v9와 **같은 walk-forward 규율**로 OOF가 필요합니다.

```
fold S ∈ {2023, 2024}
  학습 rows   data/folds/fold_S_tr.parquet   (시즌 < S)
  검증 rows   data/folds/fold_S_va.parquet   (시즌 = S, p_v9 포함)
  테이블      carry/split/role/lowrank 전부 시즌 < S 에서만 적합 (기존 fold 가 이미 보장)
  init        level logreg 의 log-odds, init_score 로 투입 (v9 와 동일)

저장   experiments/ensemble/oof/{model}_{fold}_{seed}.parquet
       columns: row_id, p            (예측만, feature 미포함)
       manifest: 모델·seed·파라미터·git hash·행 수
```

**규율**

- `test.csv`를 열지 않습니다. 계획·구현 어디에도 경로가 등장하지 않습니다.
- 시즌 S 행은 학습에 절대 들어가지 않습니다.
- 가중치·하이퍼파라미터는 **2023에서 고르고 2024는 한 번만** 엽니다. §2.2의
  −154.3이 이 규율을 어겼을 때의 대가입니다.
- 신규 파일은 `experiments/ensemble/` 아래에만 만듭니다.

## 4. XGBoost 추가 — 유일하게 새로운 축

### 4.1 기대할 수 있는 것

XGBoost가 이득을 주려면 기존 세 구성요소와 **충분히 다른 오류를 내야** 합니다.
그런데 2024 기준 A7–A9 0.96, A7–BCAT 0.81, A9–BCAT 0.83입니다. 같은 feature
행렬에 GBDT를 하나 더 얹으면 상관 0.9 이상이 될 가능성이 높고, 그러면 §2.2의
stacking 상한 +19.4를 위로 밀어내지 못합니다.

### 4.2 그래도 측정할 가치가 있는 이유

상관은 예측이지 측정이 아닙니다. XGBoost는 결측 처리·정규화·분할 규칙이
LightGBM과 달라 실제 상관은 돌려 봐야 압니다. **비용이 반나절이고 결과가
확정적**이므로 게이트를 걸고 한 번 재는 것은 합리적입니다.

### 4.3 설계

```
모델      XGBoost (hist), feats = v9 numeric_feats 101, init 을 base_margin 으로
seed      3개 (42/43/44)
fold      2023 (선택) → 2024 (최종 1회)
저장      experiments/ensemble/oof/xgb_{fold}_{seed}.parquet
```

**측정 순서** — 값싼 것부터, 각 단계에서 미달이면 중단합니다.

| 단계 | 내용 | 통과 조건 |
|---|---|---|
| **E0** | XGB 단독 OOF의 2024 BSS와, 기존 3요소와의 **로짓 상관** | 상관 **< 0.90** (다양성 존재) |
| **E1** | 4요소 로짓 stacking **2024 in-sample 상한** | 3요소 상한 +19.4 대비 **+10 이상 개선** |
| **E2** | 가중치를 **2023에서 고정** → 2024 최종 1회 | **dBSS > 0 AND dRes ≥ +10 AND paired ≥ 2σ** |

E0에서 상관이 0.90 이상이면 E1을 돌리지 않습니다 — 다양성 없는 구성요소는
정의상 결합 상한을 올리지 못합니다.

## 5. 예상 결과

| 시나리오 | 확률 |
|---|---|
| E0 탈락 (상관 ≥ 0.90) | **~60%** |
| E1 탈락 (상한 개선 < +10) | ~25% |
| E2 탈락 (전이 실패) | ~13% |
| **E2 통과** | **~2%** |

근거는 셋입니다.

1. **2024 결합 가중치는 이미 최적**입니다(+0.4). 개선 여지가 결합 쪽에 없습니다.
2. **결합 최적화의 in-sample 상한이 +19.4**인데, 이는 완벽한 stacker가 2024를
   보고 맞췄을 때의 값입니다. 새 모델이 이 상한을 크게 밀어 올려야 하는데,
   기존 세 요소가 이미 0.81~0.96으로 붙어 있습니다.
3. **BCAT 계수 부호 반전**(+0.477 ↔ −0.068)이 보여주듯, 결합 최적해는 시즌마다
   다릅니다. 이는 이 프로젝트가 다섯 번 확인한 구조와 같습니다 — 정보는 시즌
   내에 있고 경계를 넘지 못합니다.

## 6. 권고

**E0만 수행하십시오.** 반나절이면 답이 나옵니다.

- E0 통과(상관 < 0.90)면 E1·E2를 설계합니다.
- 탈락이면 **v9 유지**가 결론이고, 요청 3·4·7번은 이미 답이 나와 있으므로
  앙상블 라인 전체가 종료됩니다.

**요청 7번(weight 탐색)은 수행하지 마십시오.** §2에서 이미 수행했고, 2024 최적
가중치가 현재 값이며, 2023에서 고른 가중치를 옮기면 −79.0입니다. 이 결과는
`experiments/ensemble/` 산출물로 기록해 두는 것으로 충분합니다.

제출본은 `work/submit_v9.zip`으로 고정되어 있으며, 이 계획의 어떤 단계도 그것을
수정하지 않습니다. E2를 통과할 경우에만 새 번들 제작을 **별도로** 논의합니다.
